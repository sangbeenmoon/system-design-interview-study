## 이해가 어려웠던 내용
> 설명이 어렵거나 개념이 잘 이해되지 않았던 부분
- 일관성이 깨졌을 때 클라이언트에서 충돌을 해소하는 방법
  - LWW (Last-Write-Wins). 각 쓰기에 물리적 타임스탬프를 붙여두고 충돌 시 더 늦은 타임스탬프를 채택
  - 값 병합(merge / semantic resolution). 데이터의 의미에 맞춰 두 값을 합치는 방식. Amazon Dynamo의 장바구니가 유명한 예인데, 충돌 시 두 장바구니의 아이템을 합집합으로 합쳐. "물건이 좀 더 담기는" 실수는 "주문이 사라지는" 실수보다 낫다는 판단.
  - 사용자/애플리케이션에게 위임(siblings 보존). 충돌하는 두 값을 모두 저장해두고("형제 버전"), 다음 읽기 때 애플리케이션이나 사용자에게 "이 둘 중 뭘 쓸래?"라고 물어보는 방식.

- 벡터 시계 실무 예시
사용자가 A서버로 접속해 "노트북" 을 담음 → A: {노트북}, [1, 0]
바로 그때 앱이 B서버로 붙어서 "마우스" 를 담음 → B는 아직 A의 노트북 소식을 못 받은 상태라 {}에서 시작 → B: {마우스}, [0, 1]
네트워크가 회복돼서 A와 B가 동기화를 시도 → [1,0]과 [0,1]을 비교. 서로 자기 칸만 앞서 있으니 어느 게 최신인지 판단 불가 = 충돌. 여기서 만약 "그냥 최신 하나만 남기자"고 잘못 처리하면 사용자가 담은 물건 하나가 조용히 사라져 버림. 

- 머클 트리 원리 : 데이터를 해시로 잘게 나눠 나무 모양으로 쌓아 올려, **맨 꼭대기 값 하나로 전체를 대표**시킨다
- 머클 트리 사용 예시
  - 비트코인/이더리움 (데이터 무결성 검증)
  - Cassandra, DynamoDB
