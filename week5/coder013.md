## 핵심 내용 요약

### 8장 URL 단축기 설계

#### 해시 방식

- 해시 테이블에 <단축 URL, 원래 URL> 저장, 요청이 들어오면 원래 URL을 반환
- 해시 충돌 전략이 필요함
- 고정 길이의 URL를 만들 수 있음

#### base-62 변환 방식

- URL을 고유키로 가지는 테이블을 생성
- 각 URL에 ID 부여, 해당 ID로 base62 변환
- ID가 고유하므로 충돌이 발생하지 않음
- ID가 커질 수록 URL이 길어짐
- 서버를 확장한다면 ID 생성기가 필요할 수도?

| 구분 | 301 Moved Permanently                                                | 302 Found                        |
| ---- | -------------------------------------------------------------------- | -------------------------------- |
| 의미 | 응답이 영구적으로 다른 URL로 대체됨                                  | 응답이 일시적으로 대체됨         |
| 캐싱 | 브라우저가 응답을 캐시한 후, 다시 요청할 때 캐시한 URL로 요청을 보냄 | X                                |
| 장점 | 서버 부하를 줄일 수 있음                                             | 트래픽 분석이 필요한 경우 유리함 |

### 9장 웹 크롤러 설계

#### 구성 요소

- 시작 URL 집합
- **미수집 URL 저장소**
- HTML 다운로더
- 도메인 이름 변환기
- 콘텐츠 파서
- 콘텐츠 저장소
- 중복 콘텐츠 검증: 해시 값 비교
- URL 추출기
- URL 필터
- URL 저장소
- 이미 방문한 URL 검증: 블룸 필터, 해시 테이블

#### DFS vs BFS

- 어느 정도까지 깊숙이 탐색할지 알 수 없기 때문에 일반적으로 BFS 사용

#### 미수집 URL 저장소

- 예의
  - 짧은 시간 안에 너무 많은 요청을 보내는 일은 피해야함
  - 동일 웹 사이트에 대해서는 한 번에 한 페이지만 요청하도록 시간차를 두고 실행
  - 큐 라우터
  - 매핑 테이블
  - FIFO 큐
  - 큐 선택기
  - 작업 스레드

- 우선순위
  - 하나의 웹 사이트에서도 우선순위를 가지는 콘텐츠들이 있음
  - 이 콘텐츠를 먼저 수집하도록 우선순위를 부여
  - 순위결정장치
  - 우선순위별 큐: 우선순위가 높으면 선택될 확률 올라감
  - 큐 선택기: 우선순위가 높은 큐에서 더 자주 꺼냄

IO 비용을 줄이기 위해 메모리 버퍼에 큐를 두고 주기적으로 디스크에 기록

도메인 이름 변환은 동기 작업이기 때문에 이 결과를 캐시해두고 주기적으로 갱신하면 성능을 높일 수 있다

문제가 있는 콘텐츠 중, **거미 덫(spider trap)**과 **데이터 노이즈**를 회피하는 방법으로 사람이 수작업으로 확인하고 제외하는 작업을 AI로 대체할 수 있지 않을까?

## 인상 깊은 내용

> 특히 기억에 남거나 공감된 부분

- **301 Permanently Method**, **302 Found** (130p)

- 62진법을 쓰는 이유는 hashValue에 사용할 수 있는 문자(character) 개수가 62개이기 때문이다. (135p)

- 이미 방문한 적이 있는 URL인지 추적하면 같은 URL을 여러 번 처리하는 일을 방지할 수 있으므로 서버 부하를 줄이고 시스템이 무한 루프에 빠지는 일을 방지할 수 있다. (148p)

- ...링크들을 병렬로 처리하게 된다면 위키피디아 서버는 수많은 요청으로 과부하에 걸리게 될 것이다. 이런 크롤러는 보통 '예의 없는(impolite)' 크롤러로 간주된다. (151p)

- 도메인 이름 변환기(DNS Resolver)는 크롤러 성능의 병목 중 하나인데, 이는 DNS 요청을 보내고 결과를 받는 작업의 동기적 특성 때문이다. ...따라서 DNS 조회 결과로 얻어진 도메인 이름과 IP 주소 사이의 관계를 캐시에 보관해 놓고 크론 잡(cron job)을 돌려 주기적으로 갱신하도록 해 놓으면 성능을 효과적으로 높일 수 있다. (158p)
